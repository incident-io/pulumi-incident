# Contributing

This provider is generated. It wraps [`terraform-provider-incident`](https://github.com/incident-io/terraform-provider-incident) using the [Pulumi Terraform Bridge](https://github.com/pulumi/pulumi-terraform-bridge), which reads the Terraform provider's schema and turns it into a Pulumi package plus SDKs for TypeScript, Python and Go.

The practical consequence is that most changes do not belong here. If you want to add a resource, change a resource's inputs, or fix how a resource behaves, that work happens in `terraform-provider-incident`. Once it ships there, bumping the dependency here picks it up automatically. What lives in this repo is the mapping layer: package names, per-language settings, and the CI that publishes the result.

## Setting up

You need [mise](https://mise.jdx.dev), which manages every other tool the build needs. Everything else, including the right Go, Node and Python versions, comes from `mise install`.

```bash
mise trust
mise install
make build
```

`make build` generates the schema, builds the provider binary, and generates and builds all three SDKs. Expect the first run to take a while, since it downloads toolchains and converts every documentation example.

If you do not have `mise activate` in your shell, prefix commands with `mise exec --`.

## The main targets

| Target | What it does |
| --- | --- |
| `make build` | Everything: schema, provider, all SDKs, installed for testing |
| `make schema` | Regenerate `schema.json` and `bridge-metadata.json` only |
| `make provider` | Build the provider plugin binary |
| `make build_sdks` | Generate and build all three SDKs |
| `make build_python` | One language at a time, where `python` is any of `nodejs python go` |
| `make lint_provider` | Lint the provider. `make lint_provider.fix` fixes what it can |
| `make test` | Run the example tests. Needs `make build` first, plus `PULUMI_ACC=1` and credentials (see below) |
| `make ci-mgmt` | Regenerate the CI config from `.ci-mgmt.yaml` |

## What is generated and what is not

Hand-written, and the only files worth editing:

- `provider/resources.go`, the bridge configuration
- `provider/cmd/*/main.go`
- `.ci-mgmt.yaml`, which generates the CI
- `mise.toml` at the repo root, for tool version overrides

Generated, and overwritten by the build:

- `provider/cmd/pulumi-resource-incident/schema.json` and `bridge-metadata.json`
- everything under `sdk/`
- `docs/_index.md`
- everything under `.github/workflows/`, `.config/`, `scripts/`, plus the `Makefile` and `.golangci.yml`

The generated files are committed on purpose. The Pulumi Registry reads `schema.json` straight from the repo at a release tag, GitHub Actions can only run workflows that exist in the repo, and committing the SDKs is what lets consumers install a prebuilt package instead of generating one locally. Expect large mechanical diffs when you bump the upstream provider. That is normal, and `.gitattributes` marks `sdk/` as generated so GitHub collapses it in reviews.

Anything carrying a `WARNING: This file is autogenerated` header will lose your edits on the next `make ci-mgmt`. To change tool versions, use the root `mise.toml`, which is not generated and takes precedence over `.config/mise.toml`.

## Bumping the upstream provider

```bash
cd provider && go get github.com/incident-io/terraform-provider-incident/v6@vX.Y.Z && go mod tidy
cd .. && make build
```

Then commit the regenerated schema and SDKs alongside the `go.mod` change.

There is deliberately no cron doing this. ci-mgmt ships a daily upstream-bump workflow, but it opens a separate PR per upstream release rather than maintaining one, and upstream ships often enough (17 releases in August 2026) that they pile up when you only ever want the newest. Bumping by hand at release time is two commands and avoids the queue.

If upstream ever crosses to v7, `TFProviderModuleVersion` in `provider/resources.go` has to change too. The bridge uses it to locate upstream's documentation in the Go module cache, and if it is wrong the build still succeeds, just with no examples in the schema. Watch the example conversion rate that `make schema` prints, which should be around 90%. A sudden drop to 0% means the documentation lookup broke.

## Running the example tests

`make test` runs the programs under `examples/` through a real `pulumi up`, so it
creates, modifies and destroys resources in whatever incident.io account the
credentials point at. It needs two things, and skips without either:

```bash
export PULUMI_ACC=1
export INCIDENT_API_KEY=inc_...
make build   # the tests use the provider binary and SDKs from ./bin and ./sdk
make test
```

`PULUMI_ACC` exists so that an API key sitting in your shell is never enough on
its own to start writing to an account. It mirrors the `TF_ACC` gate on the
upstream Terraform provider's acceptance tests.

**Use a throwaway organisation.** Upstream points its acceptance tests at a
dedicated demo org for this reason. Do not point these at an account anyone
relies on.

## Things that will surprise you

**`bridge-metadata.json` replays past decisions.** It records what the bridge worked out on previous runs, including automatic property renames and resource ID handling. If you change a `ResourceInfo` in `resources.go` and regenerate, the old decision can win silently. Reset the file to `{}` and regenerate to see what your change actually produces.

**A failed lint leaves your working tree modified.** `make lint_provider` rewrites `//go:embed` to `// goembed` so the linter can run, then rewrites it back. The restore is a separate step, so if linting fails it never happens and the files are left with a comment that no longer embeds anything. Run `git grep -l goembed -- provider | xargs perl -i -pe 's/ goembed/go:embed/g'` to fix it.

**Renaming an `id` input needs `ComputeID` too.** Pulumi reserves `id` for a resource's own output identifier, so the bridge automatically renames any upstream `id` input and wires the resource ID to the renamed field. Supplying your own name makes it skip both halves, and every instance of the resource ends up with the literal ID `"missing ID"`. If you rename one, set `ComputeID` alongside it.

## CI

CI is generated from `.ci-mgmt.yaml` by [`pulumi-labs/ci-mgmt`](https://github.com/pulumi-labs/ci-mgmt), the third-party fork of Pulumi's own tooling. Use that fork and not `pulumi/ci-mgmt`: the latter refuses non-Pulumi organisations by printing a notice and exiting successfully, so it looks like a no-op run.

The fork lags Pulumi's version, which is why the root `mise.toml` pins newer Node, Python and golangci-lint than the generated config asks for. Each override says why. Expect to add more as it drifts.

Pushing to `master` runs the full build and, once publishing credentials are configured, ships an alpha to npm and PyPI, and pushes a Go SDK tag. Real releases are cut by pushing a `vX.Y.Z` tag.
